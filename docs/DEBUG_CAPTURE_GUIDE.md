# 华为耳机通用协议采集指南

HuaweiPods 正式版目前已把支持表中的 15 个机型合并到同一 APK，但其中仍有“扩展功能待复测”和“基础支持待复测”的型号。FreeBuds、FreeClip、FreeLace 等华为设备即使同属一个品牌，服务 UUID、命令编号、能力位、参数范围和返回格式也可能因系列、代际和固件而不同，因此不能仅凭设备名称跨型号复用写指令；缺失功能仍需要对应机型的真实采集数据。

项目提供两个构建：

- `release`：正式版，使用 LSPosed API 102（含自动热重载元数据）。图片身份不依赖智慧音频；只在智慧音频本来就在运行时提供 FreeClip 2 空间音频同步，不会主动启动或保活它。现代型号直接由系统蓝牙协议确认资源身份，旧协议型号可在图片设置中检索官方配色；正式版不包含协议采集界面和接收器。
- `debug`：适配采集版，固定使用 LSPosed API 101。在用户明确启用 LSPosed 作用域后，仅观察华为智慧音频调用 Android 蓝牙 API 时产生的 GATT、RFCOMM 和 L2CAP 数据，不修改、阻断或重放智慧音频的调用。

Debug 与 Release 使用相同应用 ID，不能同时安装，这可以避免两个 Xposed 模块重复 Hook。同一签名的两个 APK 可以直接互相覆盖；出现“签名不一致”时，必须改用维护者提供的同签名 APK，或卸载原版本后再安装。

## 开始前

1. 安装维护者提供的 `HuaweiPods-*-capture-debug.apk`。
2. 在 LSPosed 中启用 HuaweiPods，并至少勾选：
   - `智慧音频`（`com.huawei.smartaudio`）；
   - HuaweiPods 原有的系统作用域。
3. 强行停止智慧音频后重新打开；若新作用域仍未生效，再重启手机。
4. 断开手表、车机和其他蓝牙设备，只保留待适配耳机；采集期间不要接打电话、录音或播放涉及隐私的音频。
5. 先在系统蓝牙中连接待适配耳机，再打开桌面上的“HuaweiPods 协议采集”。授予“附近的设备”权限后，只有一副耳机时会自动选中，有多副时由测试者选择。
6. GitHub issue 为可选项。已有适配 issue 时可填写编号或完整链接，没有时可以留空并在导出后新建 issue。

自动填入名称只用于标记采集对象，不代表向导能够识别具体型号或判断设备支持哪些能力。请以智慧音频当前实际显示的功能为准。

QQ群 `1022359908` 用于待适配型号登记、测试招募、操作答疑和传输协调。采集 ZIP 请先自行检查，再按维护者说明发送。

## 引导采集

左上角的返回按钮可随时回到 HuaweiPods 主界面。

先完成页面中的两项准备确认，再点“开始采集”。每一个功能都按以下节奏操作：

1. 在采集向导中点需要采集的项目。
2. 在智慧音频中只改变卡片要求的一个设置。
3. 等待至少 3 秒，让耳机回包。
4. 返回采集向导，点“完成”。

通用向导列出了华为耳机系列可能出现的功能全集，但不会自动判断当前设备的具体能力。智慧音频没有显示或设备不支持某项功能时，直接点“跳过”，不要为了凑齐步骤反复尝试。这样日志能区分“未操作”和“设备不支持”。

向导按“设备与状态、噪声控制与音量、手势与佩戴、音效与连接质量、连接与充电盒、适配与复核”分组，覆盖智慧音频公开提供的主要耳机设置。每一项都只操作当前可见的一个设置，不显示就跳过；已处理项目会收起，误操作时可点“重做”。

功能目录参考华为官方的[智慧音频 App 功能介绍](https://consumer.huawei.com/cn/support/content/zh-cn16037781/)和各型号兼容性清单，只用于提醒测试者检查页面，不作为协议证据。默认生效且没有开关的静谧通话、无线充电，以及弹窗主题、音频服务卡片等纯应用/系统展示不单独采集；固件升级、查找、智能通知和听力健康功能仍明确排除。

自适应音量、嘈杂环境音量增强、游戏低延迟、双设备连接、开盒/充电盒提示音和智能充电各自使用独立项目，不要同时切换。带档位的自适应音量应先采开关，再按页面顺序逐档切换。音频连接中心只进入查看并等待查询完成，不添加、删除或切换其他设备；导出后还要检查日志中是否出现其他设备名称。

以下操作无论页面是否出现都不属于本采集流程，禁止执行：

- 升级固件、恢复出厂设置、重置耳机或取消配对；
- 发起/接听真实通话、录音、发送语音或采集听力/健康数据；
- 打开或记录华为账号、手机号、健康、位置、通知内容等隐私页面；
- 使用“查找耳机”或任何会让耳机响铃、上传位置的功能。

完成后点“停止采集”并导出 ZIP。压缩包包含：

- `metadata.json`：手机、Android、HuaweiPods 版本、设备名称和可选 issue；
- `events.jsonl`：按时间排序的操作标记和蓝牙事件；
- `README.txt`：文件说明和隐私提醒。

蓝牙地址会默认脱敏，但原始协议载荷仍可能包含设备标识。提交前务必解压检查；不要上传账号、健康、位置、通知内容页面、完整系统日志或与目标耳机无关的数据。

停止页会单独显示“协议事件”数量。该数字为 `0` 时，ZIP 里只有向导 marker，不能用于推导协议，应按下一节检查作用域和智慧音频进程。

## 提交与反馈

1. 先搜索 [HuaweiPods Issues](https://github.com/Nshpiter/HuaweiPods/issues) 是否已有同型号记录。
2. 已有 Issue 时，在采集向导填写编号并回到原 Issue 跟进；没有时可留空，导出、检查后再新建 Issue。
3. Issue 中请提供耳机在系统蓝牙里显示的名称、手机型号、系统版本、智慧音频版本、`protocol_event_count`、每项操作的实际表现，以及必要的脱敏采集包。
4. 普通采集 ZIP 只有在解压检查并确认可公开后，才可附到 GitHub Issue；拿不准时先只提交环境信息，等待维护者安排私下传输。
5. `protocol_event_count` 为 `0` 时只报告环境和排查结果，不要把仅含 marker 的 ZIP 当作有效协议样本。

## 结束测试环境

1. 确认采集包已经导出并妥善保存。
2. 在 LSPosed 中取消智慧音频的 HuaweiPods 作用域，重启智慧音频进程；不确定是否生效时直接重启手机。
3. 换回维护者提供的同签名 Release 版，或卸载 Debug 版。Debug 与 Release 使用相同应用 ID，不能同时安装。
4. 不再需要本地采集记录时，可清除 Debug 版应用数据或卸载 Debug 版。

## 没有记录到协议事件时

先确认 `events.jsonl` 中除了 `session_start`、`marker`、`session_stop` 外是否存在 `protocol_event`。如果完全没有：

1. 在 issue 中说明手机型号、系统版本、智慧音频版本和“只有 marker，没有 protocol_event”。
2. 确认 LSPosed 确实勾选了智慧音频，并重启智慧音频后再做一次最短采集。
3. 仍为空时，说明该版本可能没有经过当前可观察的 Android 蓝牙 API。记录环境信息并反馈，等待采集 Hook 更新。

## 维护者分析顺序

1. 用 `operation.*.start` 与 `operation.*.done` marker 划出每次单变量操作的时间窗。
2. 比较同一功能“关闭 → 开启”或不同档位之间新增/变化的 TX 帧。
3. 用随后的 RX 帧确认应答、状态通知和校验字段。
4. 至少用第二轮采集复核稳定字段与计数器/时间戳字段。
5. 只把已在真机验证的命令加入对应型号路由；未知型号继续保持只读和不可写。
