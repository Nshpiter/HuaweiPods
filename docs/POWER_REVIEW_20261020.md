# 后台刷新与耗电排查

本次没有反馈者的耗电统计、唤醒记录或对照实验，因此不能确认其手机的实际耗电归因，也不能给出节电百分比。模块运行在系统蓝牙、设置等宿主进程中，相关消耗可能计入这些进程。

## 已发现并调整

- 系统设置页的五秒轮询原先仅检查耳机仍连接。Fragment 留在返回栈时，即使页面不在前台也可能继续广播，触发电量、降噪及部分机型音频查询。现改为暂停 / 销毁时停止，返回前台恢复；只有恢复态、已挂载、可见且亮屏的页面发起周期查询。
- 设置页原先同时广播 UI_INIT 和 REFRESH_STATUS，并对 FreeClip 2 额外请求音频。蓝牙宿主对两个动作走相同刷新分支，现只发送 REFRESH_STATUS，仍由宿主查询音频与回应存活状态。
- 状态栏图标原先连接期间每 2.5 秒无条件重写，一小时约 1440 次。现保留连接或亮屏后的四次快速修复，随后每 30 秒兜底；持续亮屏一小时约 123 次，稳定阶段 120 次 / 小时。熄屏取消，亮屏恢复，断开最后一台受支持耳机时停止。这是调用次数变化，不是实测电量变化。

## 其他检查

- 常驻电量岛不是每秒刷新：收到电量报告时更新，静默续期为半小时一次。默认关闭。
- FreeClip 2 的三十秒后台电量查询仍保留，用于现有电量更新兼容；其他型号未统一启用该轮询。
- 融合中心的降噪轮询检查详情视图是否挂载且可见；RFCOMM 的短间隔读取发生在有时限的响应窗口内，不是空闲时永久读取循环。
- 本次检索未发现模块自行申请持续 WakeLock；Handler 定时回调本身不等于持有唤醒锁，也不能据此排除蓝牙链路和通知渲染的消耗。

本地回归只能验证刷新条件、频率预算和构建。若更新后仍明显耗电，应比较同一手机、相近使用时长下启用 / 停用模块的系统蓝牙耗电与 CPU 活跃时间，再结合复现日志确认，避免仅凭耗电排行榜下结论。

2026-10-20 验证结果：538 项单元测试通过，包含后台页面查询条件与一小时图标刷新预算；Debug / Release lint 无错误，Release 构建及正式证书签名校验通过。尚未进行手机待机功耗对照测试。
